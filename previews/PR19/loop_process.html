The loop process

gnss_loop reads the correlator records, closes the carrier and code loops and writes the NCO words back. It is built from the M2SDRLoop package with juliac --trim=safe (see Setting up a board). Its entry point is loop_main.

Latency

A record waits in the gateware until an epoch strobe or a full DMA buffer sends it, and a partly filled buffer is flushed after --flush-us. The strobe period and the flush time therefore bound how long a record takes to reach the loop.

--fifo keeps the loop's latency below a millisecond when the host is busy. On a Jetson Orin, SCHED_FIFO is what removed the scheduling tail under load; pinning to a core alone did not. build.sh grants the binary CAP_SYS_NICE so that this works without root.

Status report

Every --report seconds, and once more when it stops, the loop prints a status block. Each value is printed on the line after its label. The counters include:

sample_countthe gateware's sample counter
sample_overflows, record_dropssamples and records the gateware lost
epochs_folded, records_seen, strobes_seenprogress
stale_recordsdumps the driver dropped because their assignment id is not the channel's current one
stale_dumpsdumps the loop core dropped because they belong to no armed channel or predate its start
words_written, words_lateNCO words written, and words applied more than an epoch after they were due

lost_record_gapsgaps in a channel's dumps from lost records

record_age_below_us / record_age_counta histogram of record ages

What the driver does

TDMDriver is the loop core's view of the gateware:

  • Arming a channel. The driver loads the PRN's code into a code-memory slot. Slots are cached by signal and PRN, and the least recently used slot is replaced first. It carries the handover's code phase forward to a start sample arm_lead_samples ahead of the sample counter and stages the whole assignment. The gateware starts the channel at exactly that sample. The driver confirms the start from the gateware's pending and missed bitmaps. If the start sample passed before the arm landed, it reschedules the start, up to three times.
  • Writing a word. A carrier and code NCO word takes three CSR writes and applies from the channel's next sample. An unchanged word is not written.
  • Reading records. The driver reads dumps, epoch strobes and padding off DMA1. It drops a dump whose assignment id is not the channel's current one.

Nothing on the per-record or per-word path allocates.

start_device! resets the engine and starts the records. stop_device! stops the records. The channels keep correlating until the next start_device!, and the sample-tag bit that the raw stream relies on is left alone.
