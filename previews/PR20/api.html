GNSSM2SDR: the receiver's side

GNSSM2SDR — Module
GNSSM2SDR

The LiteX-M2SDR as a hardware correlator for GNSSReceiver.jl.

The FPGA — the TDM correlator gateware of gnss-m2sdr — downconverts and correlates every channel; the tracking loops are closed by a separate, allocation-free process (gnss_loop, built from the M2SDRLoop sub-package with juliac --trim=safe); acquisition, decoding and PVT run in the receiver process off the raw sample stream. This package is the receiver's side of the board: the tagged raw stream, the device-sample origin, and the command that starts the loop process.

using GNSSM2SDR, GNSSReceiver, GNSSSignals, Unitful
csr = "build/gnss_tdm_m2_x1_ch24_code4096/csr.csv"
raw = start_raw_stream(; csr, chunk = 4000, antenna = 2)
loop =
    HardwareLoop("/dev/shm/gnss-loop-m2sdr0"; spawn = gnss_loop_command(; csr, antenna = 2))
data = receive(
    loop,
    raw.channel,
    GPSL1CA(),
    4e6u"Hz";
    device_sample_origin = () -> device_sample_origin(raw),
)

GNSSM2SDR.start_raw_stream — Function
start_raw_stream(; csr, chunk, capacity_chunks = 4000, device_num = 0, antenna = 1,
                   pipe_bytes = 32 * 2^20, recorder = "m2sdr_record", host_buffers = 4096)

Enable the gateware's sample tags through csr (a LiteXCSR or the path of the gateware's csr.csv), start recorder on /dev/m2sdr<device_num> and return a RawStream whose channel delivers chunk-sample frames of antenna (1 = RX1, 2 = RX2).

host_buffers DMA buffers (8 KiB each; the default is about a second at 4 MS/s 2T2R) queue inside the recorder between its DMA reader and its write to the pipe: an unprivileged pipe cannot grow past /proc/sys/fs/pipe-max-size (1 MiB by default, 31 ms of samples), so without it a garbage collection in this process longer than that costs the recorder DMA buffers.

The reader is a sticky task on the interactive pool that blocks in the kernel, so it needs an interactive thread of its own: start Julia with -t N,M.

source
GNSSM2SDR.RawStream — Type
RawStream

A running raw sample stream, from start_raw_stream. channel delivers the chunks of one antenna as Complex{Int16} (12-bit values, tags removed); origin[] is the device sample index of host sample 0 (-1 until the first chunk has been delivered); gap_samples[] counts the samples lost upstream and replaced by zeros, resyncs[] the times the tags had to be locked onto again. close stops the recorder and waits for the reader.

GNSSM2SDR.gnss_loop_command — Function
gnss_loop_command(; csr, fs = 4e6, antenna = 1, segment = "/dev/shm/gnss-loop-m2sdr0",
                  executable = default_loop_executable(), fifo = 50, core = nothing,
                  channels = nothing, signals = "GPSL1CA", report = 10, log = nothing,
                  extra = String[])

The Cmd that starts the loop process on the board whose gateware's csr.csv is csr, for the spawn of GNSSReceiver's HardwareLoop. antenna is the RF input of the band (1 = RX1, 2 = RX2); fifo the SCHED_FIFO priority (nothing for the default scheduler; it needs CAP_SYS_NICE, which build.sh grants the binary); core pins the loop thread. The loop prints a status report every report seconds (0 for none); with log, they go to that file.

M2SDRLoop: the loop process

M2SDRLoop — Module
M2SDRLoop

The LiteX-M2SDR half of the hardware-correlator loop process: the device layer of gnss-m2sdr's TDM correlator gateware — its CSRs, the DMA1 record stream and the 64-byte record — and, on top of it, TDMDriver, the HardwareLoopCore.AbstractLoopDriver the loop core closes its loops through, plus loop_main, the entry point of the gnss_loop executable. TDMEmulator is the gateware in software, behind the same calls.

Nothing here is needed only by a receiver (no GNSSReceiver, no Tracking, no tasks), so juliac --trim=safe builds the executable from it (build.sh).

Driver

M2SDRLoop.TDMDriver — Type
TDMDriver(io, signals; fs, n_channels = 0, antenna = 1, arm_lead_samples,
          strobe_period, flush_us = 100, dma_buffer_size = 512)

The TDM correlator behind the loop core's driver API. io reaches the gateware (LitePCIeTDM or TDMEmulator); signals is the tuple of signals the loop may be asked to arm (fixed, so a trimmed binary knows every code table it needs); fs is the sample rate; n_channels = 0 drives every channel the gateware has. antenna is the RF input (1 = RX1, 2 = RX2) the band table declares and the noise reference uses; satellite arms pick theirs. arm_lead_samples is how far ahead of the sample counter an arm's start is scheduled (default 2 ms); strobe_period the epoch-strobe period (default fs / 4000, 250 µs), which with the flush_us buffer flush bounds how long a record waits before the loop sees it.

M2SDRLoop.start_device! — Function
start_device!(driver)

Reset the engine, program the strobe, the flush and the DMA geometry, open the record stream and enable the engine and the records. The RX stream (DMA0) must be draining for samples to reach the engine.

source
M2SDRLoop.stop_device! — Function
stop_device!(driver)

Stop the records and close the stream. The channels keep correlating until the next start_device! resets the engine; the tag bit is left alone.

M2SDRLoop.LiteXCSR — Type
LiteXCSR(csr_csv; device = "/dev/m2sdr0")

Named access to the gateware's CSRs, resolved from csr_csv (the csr.csv LiteX emits next to the bitstream). Close it with close.

device = nothing opens no device: every write lands in an in-memory shadow of the register file and every read comes back from it, so a driver can be exercised against a recorded register map without a board.

source
M2SDRLoop.DMAWriterStream — Type
DMAWriterStream(device; buffers = 1, buffer_size = DMA_BUFFER_SIZE)

The record stream of a litepcie DMA channel, with its DMA writer started.

Takes the channel's advisory writer lock, enables the writer, and reads in buffers * buffer_size chunks (buffer_size is the channel's DMA buffer size). close stops the writer and releases the lock again, so the channel is reusable without reloading the driver.

M2SDRLoop.tap_layout — Function
tap_layout(shifts) -> (lead, offsets, warmup)

The gateware's view of a tap layout given as sample shifts (positive = early, in record order): the code NCO runs lead samples ahead of the prompt, tap k reads replica-history entry offsets[k] = lead - shifts[k], and warmup samples fill the history before the first one is integrated. nothing if the shifts do not fit the history.
